# Four-hour prototype plan

Set T0 when the three owners start from the same main commit. These four hours are an early slice inside the original 36-hour build; they do not reset the event clock. Backend owns integration and the shared schema. Frontend and logic must deliver small increments, not wait four hours for their entire module to finish.

## H4 demonstration and honest boundary

Load the 10-site/four-branch synthetic project -> compare two sites -> fitted-model inference and bounded allocation -> incremental NPV/rank -> calculate/apply rent rescue -> change demand -> switch Current/Opens/Delayed -> choose a budget-feasible set using full-network enumeration -> open a saved printable report. Show two POI-derived daypart profiles and source/method labels. A small fitted linear model is acceptable for the initial milestone; fabricated ML output or a formula labelled ML is not.

H4 does not certify full PRD acceptance. CSV imports, user-driven project creation, advanced sensitivity, model calibration on real data, extended evidence UI and P1/P2 can follow. If any required H4 element remains unavailable, show it explicitly and record it; do not call an incomplete path complete.

## Four-hour cut ladder

Cut animation, decorative basemap, extra charts, extra infrastructure events and model complexity in that order. Use 100 cells, static GeoJSON and a table before attempting 2,000 cells/routing. Keep a real fitted artifact, conservation, NPV, rent rescue, three event states, exact/partial status, source labels and shared evaluation identity. If delay UI is late, a simple select still triggers real delayed cash flows. No P1 feature takes priority over an unconnected P0 flow.

## Checkpoints and ownership

Every 30-45 minutes: commit a bounded change; report runnable behaviour, exact interface/fixture ID, checks, blocker and next ready dependency. Backend merges compatible work after contract and real-slice checks. Use task branches so two people never overwrite main simultaneously. No forced pushes. An interface change needs backend + affected consumer agreement and schema/type/fixture updates together.

At H1 a broken data-to-screen path is the only priority for dependent work. At H2 retain a two-profile static map if richer rendering is slow. At H3 stop visual expansion. At H4 tag the exact known-good commit and record which ACs actually passed; continue toward the full PRD with remaining time.

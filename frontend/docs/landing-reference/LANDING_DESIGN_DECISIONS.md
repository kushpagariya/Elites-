# StoreScout landing design decisions

## Direction and argument
On this page, StoreScout's opportunity hex cells become one evolving investment landscape.
Inventory: incremental value, existing branch displacement, candidate sites, dayparts, POI proxies, conditional infrastructure, FailFast, rent rescue, budget, evidence provenance, one-city scope, 36-hour proposed build.
The argument follows the supplied chapters: opportunity → timing → conditional change → failure and rescue → portfolio → evidence → action.
The live interaction lets a visitor change time of day, infrastructure timing and rescue state in an explicitly illustrative city.

## Rules applied
| Source | Rule | Application |
|---|---|---|
| emil-design-eng | Purposeful explanatory motion; short press feedback; interruptible state changes | City morphs explain concepts; 160ms button press; damped scene targets |
| design-taste-frontend (installed taste skill) | Subject-derived motif, large image mass, clear type hierarchy, real working interaction | Hex geometry carries brand and scene; large editorial headings; state controls affect city |
| impeccable | Pinned brief wins; preserve product truth; inspect responsive states; design browser surfaces | User's palette and story preserved, visible focus/selection, illustrative labels, no unsupported claims |
| animate | Explanation at first-visit frequency; one token source; reduced motion ships together | lib/motion.ts; CSS interaction feedback; static chapter alternatives |
| animation-performance | Avoid React per-frame state and layout animation | Instanced geometry, ref-based scene interpolation, bounded DPR, no postprocessing |

## Explicit precedence and tooling
The user's precise master prompt and delegated creativity settle stack, purpose and visual direction; no additional concept approval gate is needed. The installed skills are emil-design-eng, design-taste-frontend and impeccable; these are the available corresponding packages, not repositories fetched anew.
